# Live research runtime

The worker invokes `executeResearchJob` after a durable database claim. The web service enqueues jobs and dispatches them; only the worker receives Qloo and OpenAI credentials.

Catalog search makes at most one official Qloo harness API request and returns at most five canonical choices. The operator must select an identity explicitly. Live event research runs a typed AI SDK 7 `ToolLoopAgent` using OpenAI Responses and `gpt-6.1-sol`, with three normal model steps and at most one additional proposal-repair step. Provider retries are disabled and a total deadline remains in force. Its tools inspect operator inventory, consult category-specific Qloo evidence, calculate feasibility and submit three drafts. It cannot publish, contact suppliers, book or spend.

If the first proposal fails deterministic validation, the tool returns only fixed rejection categories, field paths, reasons and guidance. Creative-copy reasons distinguish appearance or endorsement phrases, operational availability or rights terms, supplier names, cost or attendance claims, capacity or time claims, and private content. Feedback collects issues across all nine creative fields, with at most twelve issues, and directs the model to re-check every creative field. Rejected prose and provider diagnostics are not copied into feedback or traces. A precharged fourth model step can call only `proposeConcepts` and reuses the captured evidence; it cannot repeat Qloo discovery. A valid first proposal ends after three steps. Two invalid proposals fail after at most four model steps. All supplier, evidence, claim, cost and feasibility checks apply again to the repaired proposal.

Model call authorization runs in the awaited `prepareStep` control hook, so failed reservations and stale or cancelled jobs stop before provider dispatch. Lifecycle notification callbacks never authorize spending. The shared contract allows four model calls per research job; default daily model allowances are 90 globally and 12 per workspace.

Qloo calls use fixed official harness CLI commands. Each subprocess permits one GET to the hackathon `/search` or `/v2/insights` endpoint, forbids redirects and retries, and caps time and response bytes. Calls are precharged against durable per-job, workspace and global allowances before dispatch. Fresh normalized cache entries avoid another provider charge. Cancellation and changed-input checks occur between operations and again before the database applies a result.

Provider inputs exclude supplier names, scopes, addresses, tokens, contacts, commitments and bookings. Obvious contact details in abstract freeform briefs are redacted; catalog queries containing them are rejected. Public evidence contains canonical names, category, capture time, query fingerprint, rank and interpretation boundaries. Raw provider responses are never stored in the repository or used as model instructions. Missing candidates remain omitted; affinity never becomes attendance probability, rights or supplier availability. Supply fit is an editorial interpretation of operator-confirmed influence mappings.

The model chooses each composition's format, inventory IDs and exact cultural entity/evidence references with a purpose. The application assembles public descriptions, offer names, cultural names and ingredient lists from those validated choices. The model cannot submit those factual prose fields. Title, subtitle and rationale remain explicitly creative hypotheses; appearance, endorsement, fee, licensing and availability claims are rejected. The compositions are generative choices over current evidence and inventory, not fixed authored cards.

Costs use entered supplier fees, fixed overhead and per-guest costs. A free, host-funded event is feasible when its supplied costs fit the entered budget; break-even is then not applicable. Missing operational data remains unresolved. Failed live calls never return authored samples.

Schedule feasibility uses the operator's typed program and setup starts and durations through the shared schedule checker. Exclusive program overlaps, slots outside the event window and setup finishing after its own program start are violations. An operator can explicitly allow a service to overlap. Missing starts or durations remain unresolved; the worker never parses scope prose or invents a start from doors. Known impossible durations still fail without an exact start. The model receives these typed constraints with anonymized offer labels, and schedule diagnostics use offer IDs instead of supplier names.

## Worker hosting

Run `pnpm exec tsx apps/worker/index.ts`. Local mode polls the durable queue and authenticates `POST /dispatch` with a random `WORKER_DISPATCH_TOKEN` of at least 32 characters. Cloud Run mode sets `WORKER_AUTH_MODE=cloud-run` and requires a private IAM-protected Cloud Run service. Cloud Tasks supplies its Google OIDC token; the application relies on platform IAM only when `K_SERVICE` exists. Cloud Run mode handles one targeted `{ "jobId": "uuid" }` per request and performs no background polling. A busy worker returns 429 so Cloud Tasks can retry. A recovery request with `{}` claims the next queued or expired job. Configure the task deadline above the 90-second research deadline. `GET /healthz` exposes only status, activity and the last heartbeat.

Tests use synthetic identities and injected transports/models. `pnpm test` performs no paid provider calls. A passing synthetic test does not establish live provider success.
